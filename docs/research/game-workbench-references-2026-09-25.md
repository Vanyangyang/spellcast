# 游戏开发工作台：公开资料与组件复用建议

调研日期：2026-09-25。范围：面向独立开发者，支持当前 R0–R2 新规划。

本轮产物是资料筛选和产品建议。文中的“资料事实”来自官方文档、作者文章或项目仓库；“用于 Spellcast”与优先级是结合当前实现提出的判断，尚未作为功能实现。

## 1. 调研后的主要判断

1. 工作台的价值要落到具体动作：修改条件、检查参数、逐步走流程、观察变化、比较方案、记录验收结果。
2. 系统图、参数表、曲线和试走面板应引用同一份项目对象。系统骨架保持稳定，当前内容与本次观察结果叠加到对应位置。
3. 原子组件按交互能力扩展，游戏对象按业务含义分类；两者通过对象引用与字段定义连接。
4. 当前优先做条件/结果编辑、参数表与曲线、流程试走。涉及完整游戏模拟和自动平衡的能力，需要等明确的规则与分析目标。
5. 保留原 Canvas 入口、本地用户数据、锁定和版本机制。公开产品作为交互与实现参考；新游戏内容仍由新的规划资料确定。

## 2. 最值得利用的资料

### A. articy：条件、流程试走与变量变化

**资料事实：** articy 的 Flow 支持连接点、分支与嵌套。Simulation Mode 可以评估流程中的条件，显示无效选择及失败部分，并查看变量的初始、前一步和当前值。不能自动求值的外部函数需要另行提供结果。[Flow](https://articy.com/help/adx/Flow_WhatsThis.html) · [Simulation Mode](https://www.articy.com/help/Presentation_Simulation.html)

**用于 Spellcast：** 扩展条件/结果组件与试走面板；点击一条路径，显示它为什么可走、需要哪些输入、改变了哪些值。遇到尚未实现的游戏动作时停止并说明需要什么结果。手填结果应记录为本次测试输入。

**边界：** 图上的说明文字不会自动变成可执行规则；预演必须声明实际支持的规则范围。

### B. Inky：编辑与预览之间保持上下文

**资料事实：** Inky 支持边写边预览，重新编译后可根据已有选择回到先前位置；错误列表能定位到源文件与行，编辑器也会观察外部文件变化。仓库列出 MIT 许可证。[Inky 官方仓库](https://github.com/inkle/inky)

**用于 Spellcast：** 修改一个新手流程节点后保留试走路径，重新检查从哪里开始发生变化；问题条目可直接定位到对象和字段。减少“改一次就从头找一遍”的操作。

**边界：** 借鉴编辑器行为。是否使用 Ink 语言，要由实际叙事需求决定，不能据此改写 VESPERIX 的全部规则。

### C. Machinations：分别观察单次过程与结果分布

**资料事实：** Machinations 用资源流和系统动态建模，提供单次 Play 与多次随机 Predict，以及图表和方案比较。[官方产品概念](https://machinations.io/docs/what-is-machinations-systems-simulation-tool)

**用于 Spellcast：** 参数面板应能回答“改了哪个输入、哪个输出改变、结果对这个值是否敏感”。先支持小范围公式与曲线比较；出现明确随机规则后，再考虑多次运行和分布图。

**边界：** 模拟结果取决于模型。模型假设、初始条件和重复次数应随结果保存；结果不能自动充当真实玩家体验的证据。

### D. Unity / Ink Player：把观察绑定到实际运行实例

**资料事实：** Unity Visual Scripting 文档区分运行前的图检查与运行时错误定位，并说明预测检查可能有误报。Ink Player Window 可以连接运行中的 Story，查看状态、历史与变量。[Unity 调试文档](https://docs.unity3d.com/Packages/com.unity.visualscripting@1.9/manual/vs-debugging.html) · [Ink Player Window](https://github.com/inkle/ink-unity-integration/blob/master/Documentation/InkPlayerWindow.md)

**用于 Spellcast：** 后续接入真实游戏时，记录具体运行实例、源码/配置版本、对象 ID、输入与结果；从节点打开对应的运行轨迹或错误。验收结果关联到被验证的版本。

**边界：** 这些是集成范式，尚不是当前工作台已具备的 Unity 适配能力。预演记录与实际游戏运行记录需要清楚标示来源。

### E. X6：复用图编辑能力

**资料事实：** X6 支持 SVG/HTML 自定义节点、连接点和事件，提供选择、对齐线等图编辑扩展。3.x 将常用插件并入主包。项目采用 MIT 许可证。[X6 官方仓库](https://github.com/antvis/X6) · [节点与连接点](https://x6.antv.antgroup.com/api/model/node) · [3.x 插件整合说明](https://x6.antv.antgroup.com/tutorial/update)

**用于 Spellcast：** 优先评估把连线、选择、快捷键、缩放和历史交互收敛到共用编辑层。先用一种可编辑节点验证适配，保护已有布局和引用。

**边界：** 图引擎的内存撤销并不等于项目对象的持久化版本。涉及真实设计值的修改，仍要走现有对象命令、锁定与版本检查。

### F. Tabulator + ECharts：参数表和曲线使用同一份数据

**资料事实：** Tabulator 支持可编辑单元格验证，并提供阻止、标记和手动检查模式；ECharts 的 dataset/encode 用于把同一数据集映射到不同图表维度。[Tabulator 验证](https://www.tabulator.info/docs/6.x/validate/) · [ECharts Dataset](https://echarts.apache.org/handbook/en/concepts/dataset/)

**用于 Spellcast：** 参数组件组合为“可编辑表格 + 曲线 + 当前/候选/局部值说明”。选中表格行可定位曲线与依赖节点；曲线中的点能回到参数对象。草稿允许继续编辑，并明确提示问题。

**边界：** 图表库负责呈现，公式计算与游戏规则仍需明确实现；表格中的校验也不能替代服务端保存检查。

### G. SQLite：日常备份可采用现有数据库机制

**资料事实：** SQLite Online Backup API 支持从运行中的数据库生成一致快照，并可以分步复制。[SQLite Backup API](https://www.sqlite.org/backup.html)

**用于 Spellcast：** 规划自动本地备份、保留策略与恢复检查；使用数据库备份接口生成可验证副本。

**边界：** 应用中的版本历史与数据库备份分别解决内容回溯和文件恢复问题。备份继续放在本地用户数据位置，进入 Git 由主动导出决定。

### H. MDA 与 The Door Problem：从玩家体验追溯到具体规则

**资料事实：** MDA 将游戏分析分为机制、动态过程与体验；Liz England 的 The Door Problem 用一个具体对象展现交互条件、玩家理解、实现和测试问题之间的联系。[MDA 原论文介绍，2004](https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/) · [作者原文，2014](https://lizengland.com/blog/the-door-problem/)

**用于 Spellcast：** 体验钩子组件保留“希望玩家感到什么、看到什么、做什么、得到什么反馈”，并能追到相关规则、数值和验收问题。新手流程由具体体验问题推动，而不是仅按系统名称填表。

**边界：** 这些是设计分析方法，不能直接转换为一个“好玩分数”。它们也没有规定我们必须采用某套进度标签。

## 3. 与现有仓库对应

本次直接核对 `package.json` 与 `src/project-planning-model.ts`：

| 当前声明或实现 | 可复用方向 | 仍需做的接合工作 |
|---|---|---|
| `@antv/x6` 3.1.8 | 节点、连接点、选择和共用图编辑交互 | 视图变更与业务命令衔接；保留用户布局；同一对象多个视图实例 |
| `echarts` 6.1.0，devDependency | 参数曲线与结果比较 | 将对象/运行记录映射为 dataset；检查新原子的打包入口 |
| `tabulator-tables` 6.5.2，devDependency | 可编辑参数表 | 单元格与对象字段对应；草稿、锁定、冲突和批量提交语义 |
| 参数已有 value/unit/min/max/formula/variants | 当前值、候选值和约束 | `formula` 目前是文本；计算行为、依赖与曲线尚需定义 |
| 规则已有 trigger/condition/effect | 规则编辑与说明 | 结构化条件与明确的求值范围 |
| 钩子已有 cue/action/payoff/continuation | 体验目标与反馈设计 | 更直接的编辑组件以及与具体内容、验收问题的引用 |
| SQLite 对象、历史、工作记录 | 保存、回溯与结果关联 | 跨对象改动提案、日常备份及与实际实现的可靠映射 |

依赖已经声明，不等于这些功能已经接进工作台。X6 顶层许可证为 MIT；Tabulator 为 MIT；ECharts 为 Apache-2.0。正式复用具体源码和资源时需保留相应许可证材料。[Tabulator 官方仓库](https://github.com/tabulator-tables/tabulator) · [ECharts 官方仓库](https://github.com/apache/echarts)

## 4. 建议扩展的组件

以下是调研后的产品建议，不是新增的强制对象分类。

| 组件 | 用户直接操作 | 与已有数据的关系 | 首个验收点 |
|---|---|---|---|
| 条件/结果编辑器 | 添加条件、分支和状态变化 | 规则对象及其字段、引用 | 能说清一条边何时可走、影响哪些值 |
| 参数表 + 曲线 | 修改候选值、比较曲线、定位依赖 | 同一参数 ID；局部值继续在关联上 | 修改共用值后，沿用者与局部覆盖者表现清晰 |
| 体验步骤卡 | 编辑玩家目标、行为、反馈与继续动机 | 内容、流程、钩子的引用 | 从一个体验问题找到相关规则和验收项 |
| 流程试走面板 | 设置初始条件、选择下一步、查看前后变化 | 单独保存本次路径与输入，引用来源版本 | 改一个条件后能看见路径变化并回到先前位置 |
| 改动提案 | 查看前后差异、影响范围、采纳或保留方案 | 基于已有对象版本与草稿机制 | 一次改动涉及哪些对象清楚可查，冲突不覆盖 |
| 验收记录 | 编辑步骤、预期、实际结果，附运行证据 | 工作记录关联具体对象/实现版本 | 能从结果回到当时被验证的改动 |

组件共享引用、选择、编辑、保存与版本能力。通用 Canvas 自由组合它们，游戏开发入口组织系统语义与内容叠加。同一对象在图、表、曲线中的显示仍引用一份数据。

## 5. 建议实施顺序

### 第一段：让一条真实新手流程可编辑、可讨论

- 从新的 R0–R2 规划确定一条具体流程及所用系统。
- 先补条件/结果编辑和参数表，保留当前自由文字说明。
- 未定内容允许明确留空；已填写内容接受引用、类型和数值约束检查。
- 用同一对象在节点、详情和参数表之间切换，确认保存范围与引用一致。

### 第二段：增加可追溯的流程试走与改动提案

- 保存初始条件、选择路径、每一步的变量变化与来源版本。
- 只运行明确支持的计算与条件；未实现的游戏动作交给对应执行环境或暂停。
- 对比两次改动，定位分歧从哪一步开始，并能回到对象继续编辑。

### 第三段：接入实际实现与验收结果

- 建立新规划对象到实际代码/配置的明确映射。
- 记录执行差异和游戏运行证据，让结果回到对应对象版本。
- 与真实规则一致的数值分析再按需扩展到批量随机模拟。

## 6. 本轮取舍与仍未证明的事项

- articy、Inky、Machinations 提供值得借鉴的操作范式；本轮未要求购买或接入它们的服务。
- 外部产品案例没有证明我们的新手流程设计正确，也没有完成 VESPERIX 的运行验证。
- MDA 与 The Door Problem 是历史设计资料；软件文档按本次访问内容记录，不把抓取时间当成产品发布时间。
- 部分页面抓取失败或只返回导航（例如 Machinations Debugger 页面）；没有据此声称已核实断点/单步调试细节。
- 本轮没有新增依赖、复制外部源码、导入旧配置或修改应用中的游戏内容。文档属于可评审的研发资料；本地游戏数据仍与源码分开。
