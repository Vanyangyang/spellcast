# 游戏内容工作台：本轮交付与验收

日期：2026-09-26。用户已授权实施。本地 0.4.12 已重新构建、打包、安装并重启；版本字符串不变。本轮没有提交或远端发布。

## 现在可以使用

- 游戏开发 → 写内容：不用先建系统，先写正文；未填名称时用首行命名。
- 正文可分为有稳定 ID 的有序片段；可选正文、理由、备选、问题角色，支持 Markdown 阅读、预览、来源、顺序调整和撤销最近一次移除。
- 系统和流程对象可以连续阅读直接关联的设计及真实共用/局部数值。编辑一段后可返回原阅读位置。
- 系统或已保存流程步骤中的“在这里写内容”自动预置归属或锚点。内容持有关联，不改动锁定流程的版本。
- 旧正文保持兼容，显式转换为一个片段，原字符串完整保留；取消转换不改保存数据。
- 阅读对象及滚动位置保留到重新打开；对象目录搜索包含正文。
- 内容历史按片段显示修改前后、角色和来源；锁定历史仍保留。
- 保存后锁定、明确解锁、版本与请求收据保留。新片段存在时，旧写入方提供 planning 却遗漏 sections 会被拒绝。
- 含片段的当前或历史数据导出为 v4；旧格式仍可导入，伪装成旧格式的片段数据会被拒绝。

实施契约：`docs/game-content-workspace-contract.md`。Claude 候选意见与主任务取舍：`docs/research/claude-content-workbench-proposal-2026-09-26.md`。

## 独立复核后的修正

后端执行者完成后进行了只读前端复核，主任务核对并修正三项风险：

1. 不同位置的新内容草稿曾可能复用同一个项目级草稿。现按位置区分，旧草稿继续可恢复；目录列出本地草稿。
2. JSON 键顺序不同曾可能把未修改内容误判为脏草稿。现按字段值比较。
3. 旧冲突处理只更换 revision，可能覆盖对方新增关联。现保留基准快照，合并双方无冲突修改；同一字段都改动时显示比较并要求明确选择。没有基准的旧草稿不会自动强行合并。

主任务新增浏览器检查验证上述三条。独立复看未再发现具体遗漏；独立复看本身是源码审查，不替代运行证据。

## 本轮边界

- 新功能交互证据来自同一最终前端构建的隔离浏览器。没有对安装版原生窗口逐个控件做自动化验收。
- 真实项目内容未改变；没有把测试片段、示例或旧游戏配置写入 VESPERIX。真实 R0 新手内容的完整性仍需在录入当前材料后验收。
- 没有新增聊天自动采纳、通用富文本/块引擎、跨对象自动提取、自然语言转执行规则、Unity 或玩家体验验证。
- 片段沿用所属对象的锁与版本；并发修改同一个数组会要求明确选择，不会猜测作者意图。
- 原 anchors 的旧客户端缺省语义没有单独重构；本轮新写入保留完整锚点，新 sections 有额外遗漏保护。
