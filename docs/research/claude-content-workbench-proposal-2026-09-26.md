## 主任务建议

优先建设“骨架定位 + 此处的完整内容稿 + 引用已有设计对象”。打开一个系统或步骤，能够连续阅读相关游戏内容并直接编辑，不再由用户在多个表单中拼出上下文。

内容稿应先容纳自然书写。每个片段自动拥有稳定标识，用户可以按需标为正文、理由、备选或问题；这些标签用于组织阅读，不表示已确认、已实现或已验收。不要求每段分类，也不按句子自动拆碎。一个段落可包含多行 Markdown、对白和说明。

系统图和流程展示同一份项目内容；正文中的共用参数及规则采用明确引用，不另抄一份。讨论原话保留在原聊天，采纳的内容和取舍可写入稿件并保留出处。

## 最小实施范围候选

1. **连续阅读与上下文编辑。** 在系统图和流程步骤增加阅读此处、在此写内容；正文占主要窗口面积；关系、来源、历史放在辅助区域。相关对象按显式作者顺序或分组显示，不靠启发式伪造叙事顺序。
2. **轻量片段。** content 内增加可选有序片段，每项自动 ID、正文与可选角色、来源；旧 body 保持可读，转换必须可预览，避免新旧正文并存为两份可编辑真源。仍以所属对象的锁、版本和冲突检查保护，不新建通用块数据库。
3. **保留位置和修改依据。** 就地编辑单片段，保存后各视图读取同一对象；历史展示人能读懂的正文变化。锁操作历史仍保留，可在显示时折叠。
4. **只引用已有原子。** 数值、规则、钩子继续独立存在，片段或同位置的关联区显示保存值。暂不自动抽取，不把自然语言转成执行条件，不扩展试走计算。
5. **兼容与恢复。** 明确旧写入方的拒绝或保留策略，补导出/导入和重启恢复；不能靠增加可选字段就宣称兼容。

若实施，应先做连续阅读视图来验证真实内容的呈现，再接片段保存与历史；可分两个可评审的增量。是否在同一次交付完成取决于实际代码改动，不应为了“最小”省掉数据完整性。

## C. 组织、保存与复用

**四层，各有唯一真源：**
- 骨架：系统、流程、步骤，只管位置与顺序。
- 篇章：content 内的有序段落，带角色、出处和引用。
- 原子：规则、钩子、数值、共享内容。
- 讨论原件：Codex 线程、Canvas 回复，只被引用，不被复制。

**完整内容与原子的边界：**
- 段落只在三种情况下升为原子：被 ≥2 处复用、参与试走计算、需要独立确认或锁定。否则留作段落。
- 提取就是移走文字、在原位内嵌引用，并自动维护 uses/belongs_to。先例：变量绑定参数时会自动补 uses（`src/game-flow-editor.ts:110`）。

**讨论、当前方案、未定问题如何共处：**
- 篇章只沉淀结论、理由、备选、待定。
- 原话留在原处，用 SourceReference 指向线程或"Canvas 对象@版本"。
- "复制上下文"改为带段落 id 的 Markdown，Agent 按 id 回写。

**Canvas 只复用渲染层：**
- 可复用：`renderLightText` 是纯函数（`src/light-text.ts:206`），回复、批注、原生文字已在共用，可直接渲染篇章。阅读器的"目录 + 单原子聚焦 + 记住位置"按同样模式另写。
- 不嵌 `mountReplyBoard`：它的 onAction 把提问和选择路由回 Agent（`src/replies.ts:46-60`），草稿以 Canvas 对象为键（`src/reply-drafts.ts:29-30`），会越过数据边界。
- 不复用 Canvas 阅读器：它把 `frame.content` 搬进对话框（`src/canvas.ts:645`），与 Canvas 帧耦合。
- 以后要把规划对象放上 Canvas，仿 `work_record` 卡片只存 ID（`src/types.ts:58`）。

## D. 实现路径对比

- **路径一：现有对象 + 组合阅读 + 就地编辑。** 零 schema 改动，只改前端。能解决连续阅读和就地写；解决不了当前/备选/待定的区分、按段回看、无重复提取。
- **路径二（推荐）：路径一 + content 内最小段落结构** `{id, role: current|why|option|open, text, refs?, source?}`。
  - 代价：Rust 校验、导出升版（`PlanningFields` 是 `deny_unknown_fields`，`spellcast-bridge/src/project_planning.rs:8`）、测试和编辑器。
  - 有个坑要先补：`put_object` 整体替换 planning（`spellcast-bridge/src/project_record_store.rs:1086`），漏写某个字段的 Agent 写入会把该字段静默清空。现有的 anchors 已有这个风险（`project_planning.rs:32-33`）。新字段应设为 Option，已有非空值时省略即拒绝；anchors 一并修。
- **路径三：通用 block（复用 ReplyBlock）。** 不必要，而且有害：sequence 与流程步骤、comparison 与数值候选会各成一套新的双份真源，还会把 Agent 反馈语义带进项目库。

**交付顺序：** 先交付路径一的阅读视图，立刻用真实段落验证；同一轮接上段落结构。实在要砍，可以砍 refs 和提取（原子先单独建，用现有关联挂）。段落 id 和角色不能砍，否则过不了"什么未定"这条验收。
