# Spellcast 下一步改善提示词

以下内容可以直接复制给接续任务。2026-09-15 的代码盘点确认了这些缺口；它们尚未因为本次源码推送而被修复。

---

请基于 Spellcast 当前代码继续改善 Canvas 工作台，保留已有能力，以「组合一个 Idea → 在原处编辑和讨论 → 最后明确发送给原 Codex 任务 → 结果回到原内容」为主流程。先核实代码和现有验收记录，区分已实现、已验证和待改善，随后按下面的优先级实施、验证，不只改名称或文案。

1. **先收敛回复与历史。** 每次明确发送是一条请求；选择方案、修改内容、拖动和重排只保存本地状态，不单独投递。Idea 内呈现用户留言、Agent 回应及可定位的画布结果；全局回复入口聚焦需要处理的请求与新结果。来源 ID、版本、耗时、投递协议、绑定表单等技术细节移入诊断。旧操作日志仍可查找，不能混成新的待办，不擅自删除用户历史。
2. **修复历史分类的已知遗漏。** 当前 `src/feedback-inbox.ts` 只把无 Desktop 记录的旧 `queued` 显式留言归入历史，漏掉了旧 `waiting` 留言。已知有来源绑定缺失、从未尝试投递、没有处理回执的旧留言仍占据「待跟进」。用可靠的投递和来源证据分类；不能简单把所有 `waiting`、未关联或较老的请求都隐藏，也不能掩盖刚刚发送失败的请求。无法证实原任务删除时只显示「未关联/来源信息不完整」；只有实际查询确认后才标记「已删除」。旧记录不能因刷新、重新绑定或打开面板被自动重发。
3. **统一组件与 Idea 的操作粒度。** 已有文字、图片、矩形/椭圆、比较、关系图、步骤，以及 Agent 提供的交互作品。Idea 是这些组件表达的完整想法，拥有标题、说明、有序成员和来源。目前部分回复仍是多块内容共用一个容器，成员只能属于一个组合。先补齐组件级选择、编辑、重排、加入/移出组合、针对组件或整体继续讨论的一致体验，保留稳定身份和版本。共享引用、更多原子类型和新的模型服务先评估真实需要，不默认扩建。
4. **保持来源、派发和编辑保护。** 按工作区、再按任务浏览，默认发送给原任务；切换任务必须明确确认。不同工作区或相邻时间的想法不能自动连线。发送携带最终选区、组件版本、组合成员和必要交互状态；重复点击、响应丢失或重试不能重复执行。用户草稿、内容与布局不得被 Agent 静默覆盖；有冲突时保留可审阅提案。没有新的可定位结果时，不把当前画布内容冒充某次历史回应。
5. **完整验证再交付。** 先用隔离数据完成 Browser Use 验证：两个工作区、多个任务、无来源旧记录、新发送失败、已删除任务、默认原任务和换任务确认、组件组合/编辑/重排、仅最终发送产生一次投递、结果回写与刷新重启。覆盖版本冲突、重复请求和断线重试。分别报告代码测试、隔离浏览器验证、真实 Codex 回发的证据；不要用 fixture 成功代替真实模型回合，也不要用提示词提醒模型发旁念来冒充被动触发验收。

保留当前仅 Codex 可选的一键完整接入。保护现有用户数据和无关工作区改动，不运行会重放真实历史请求的测试，不为测试额外启动重复的生产窗口。完成每个阶段后说明实际行为变化、验证结果和剩余限制；如需更新本机运行版，使用已有备份、正常关闭、替换和数据保留核对流程。
