# 游戏内容阅读与编辑：本轮实施契约

2026-09-26，用户在完成 Claude 咨询与主任务取舍后授权“好的开始”。

## 产品范围

- 系统骨架保留；同位置的内容、规则、钩子和数值组合阅读，保留对象身份并直接编辑。原 Canvas 入口、数据与反馈语义独立。
- 增加“写内容”入口，默认 content，可不依赖骨架保存；从系统/步骤发起时自动带归属/锚点。挂接由内容持有，不改动或解锁流程。
- content 支持有序、稳定 ID 的片段，角色可选正文/理由/备选/问题，不推断确认状态。先完整写下，再按需分段；禁止自动逐句拆分。
- 旧正文仍能阅读编辑。显式转换成一个正文片段，完整保留原字符串；取消不修改保存内容。
- 已有规则、钩子与参数保持唯一对象；阅读区通过现有关联展示保存值。第一轮不自动提炼、不搬移跨对象文本、不增加通用 block 引擎或模拟。
- 保留保存后锁定和显式解锁，历史显示人能阅读的片段/正文变化；记住内容选择与阅读位置。
- 不自动导入真实游戏文档或旧配置，不编造正式 R0 内容。产品能力用隔离示例测试，真实内容验收单独标明。

## 数据契约

PlanningFields 增加可选 `sections: ContentSection[]`，仅 kind=content 可用。ContentSection 为：

`{ id: string, role: "body" | "reason" | "alternative" | "question", text: string, references?: SourceReference[] }`

- ID 在对象内唯一且稳定，非空最多 128 字节。最多 128 项；每项 text 最多 32 KiB，正文合计最多 128 KiB；空片段可保存为未完成记录。role 默认 body，references 默认空；引用沿用 SourceReference 的校验。
- sections 存在时 body 必须为空；不存在时沿用旧 body。不能形成两份可编辑正文。
- 整体省略 planning 时继续保留旧 planning。已有 sections 的对象，如更新提供 planning 却省略 sections，必须拒绝，不能把新内容清空。显式 sections=[] 表示有意清空；禁止隐式回退旧 body。
- 保持锁、expected_revision、历史、幂等收据和图引用校验。恢复历史允许显式恢复旧 body 格式。
- 导出含 sections 的当前对象或历史时使用格式 v4；原格式无新内容保持原规则。v1-v3 仍可读。导入、导出、历史与重启保留片段。
- 旧 anchors 的省略更新风险不能因为本轮新增 sections 而扩大；新增写入必须保留完整 anchors。若修改 anchors 缺省语义，需要单独验证兼容性，不悄悄改变所有旧请求。

## 范围分工

- 主任务：前端数据类型、内容编辑/阅读、上下文入口、历史呈现、整合与最终检查。
- 独立后端执行者：Rust 段落模型、校验、完整性保护、导出/导入以及聚焦测试。不得编辑前端、文档或真实数据库。
- 浏览器检查使用隔离存储/夹具；构建安装前备份真实数据并对比。

## 可观察验收

1. 不建骨架也能保存一个未确认内容；多段有序，Markdown 可读，问题角色可见。
2. 从系统或现有步骤写内容后，关联位置正确，流程版本不变。
3. 一处连续看到正文和相关设计，长文可滚动；编辑入口不会丢失阅读位置。
4. 旧正文的显式转换、取消、保存、局部片段修改、重新打开与历史差异可验证。
5. 引用同一参数后展示共用值；没有重复数据副本。
6. 缺省 sections 的旧写入被拒，锁定写入被拒；失败不产生半份记录。
7. 导出、导入和真实服务重启保持片段/引用/锁；原 Canvas 检查继续通过。
