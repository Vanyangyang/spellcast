# 已读同步性能 — 2026-09-12

结论：有少量后台开销。增加缓存后，在当前机器上测得的稳定状态开销已处于合理范围；不把计时结果当成整机 CPU 占用率或所有机器的保证。

## 优化

- 保持现有每秒一次的后台线程轮询，通知内容变化时才更新窗口。
- 没有待处理通知时不读取 Codex 已读文件。
- 缓存一次成功同步对应的文件大小、修改时间和完成轮次；它们未变时，只查询文件元数据，不重新读取/解析 JSON，也不进入已读同步的数据库处理。
- 文件变化或新完成轮次出现时立即重新同步。每 30 秒完整复查一次，防止相同大小、相同时间戳的变化被永久漏掉。
- 仅确实移除了完成通知时再次查询待处理列表，省去原先每轮固定的第二次查询。
- 缓存只保留路径、元数据和轮次 ID；不持有完整 Codex JSON。超过 16 MiB 的文件在读取内容前就被拒绝，继续保留气泡。
