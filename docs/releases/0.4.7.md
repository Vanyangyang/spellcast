# Spellcast 0.4.7 — keep the selected Canvas task visible after reconnect

The Windows installer was built locally. The release workflow also builds macOS and Linux packages.

## Fix

When an original Codex task is reconnected, its binding may supply a workspace that older Canvas content did not record. The content is then grouped under that workspace. Canvas now follows the visible selected card to its new workspace and task scope, so reconnecting does not make the card appear to vanish or clear the selection. Multiple selected cards that move to different workspaces remain visible through the All workspaces scope. The underlying content and placement are unchanged.

## Verification

- `npm run build` and `node scripts/check-content-origin.mjs`.
- `node scripts/check-workspace-canvas.mjs` in an isolated browser fixture: an unbound selected card receives a Codex binding, stays visible and selected, and no backend writes occur.
- `node scripts/check-canvas-recipient.mjs` for explicit reconnect and send-back gating.

The local UI regression uses fixtures; it does not claim a live Codex task was sent a Canvas message.
