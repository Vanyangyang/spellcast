# Spellcast 0.4.12 — completion notification visibility and read sync

Completion notifications now stay visible when the pointer enters or leaves a card. Opening the matching Codex task can also clear its notification when Spellcast missed the brief unread state.

- Show the completion window through Tauri so its stored visibility agrees with the Windows window. Pointer pass-through changes no longer reapply a stale hidden state.
- Keep observed unread-to-read transitions immediate. For a missed transition, accept a stable Codex snapshot saved after completion once the three-second notification propagation grace has passed.
- Preserve unread notifications, later turns, unavailable or stale snapshots, changed account/host scopes, and tasks whose metadata has not arrived yet. Existing unread observations retain their meaning during the schema upgrade.

## Validation

- Completion-related Rust tests: 28 passed, 1 existing ignored test.
- Full local Windows test run: 200 workspace tests passed; 121 desktop library tests passed, with 2 ignored tests.
- Isolated Windows native regression: 22 checks passed, covering pointer pass-through, focus, hide/show, missed read transitions, and retention of a new completion after an older read snapshot.
- The pointer disappearance fix was checked on the actual Windows desktop. The missed-read path was checked with isolated notification/state fixtures; a new live Codex completion-to-click cycle was not observed after installing that fix.
- Package builds run from the tagged commit in GitHub Actions. The local unfinished Canvas changes are not part of this release.

## Running the native regression on Windows

Build a separate test identity before running `npm run check:completion-visibility`:

```powershell
$env:TAURI_CONFIG = '{"identifier":"com.spellcast.visibility-test","app":{"windows":[{"label":"main","title":"Spellcast visibility test","visible":false}]}}'
cargo build --manifest-path src-tauri/Cargo.toml --bin spellcast
Remove-Item Env:TAURI_CONFIG
npm run check:completion-visibility
```

The test uses isolated databases and the actual native window commands without moving the system pointer. It refuses an executable with the normal app identity, so it cannot accidentally attach to the installed app's single-instance window. Rebuild with the normal configuration before using the debug executable for ordinary development.
