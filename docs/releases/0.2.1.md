# Spellcast 0.2.1 — thoughts where you are working

The Agent's current task is the source of a bubble's content. The user's current foreground window determines its display. The previous implementation incorrectly treated the Spellcast board's monitor as the active monitor.

## Changes

- Read the operating system's active screen when each bubble is delivered. Windows uses the foreground window's monitor; macOS uses the active screen API. During a focus transition, fallback is the pointer's display, then primary. Identical display model names are not treated as the same monitor.
- Use physical coordinates for native bubble movement so placement does not depend on the new window's initial scale factor.
- Separate selected board mode from actual keyboard focus. Switching to another app resumes bubble delivery and preserves board content. Returning to the board suppresses bubbles. Explicit pause remains independent.
- Expose `board_focused` alongside `surface` in health and MCP read results so clients can distinguish these states.
- Refine bubble typography, shadows, labels and the star's placement. The star remains inside the bubble, with room reserved so it does not cover the words.
- Expand the film to begin with a real working document and native task-related bubbles, before adoption and the existing board interaction.

## Verification

- Windows: 41 workspace tests and 9 desktop tests passed. The opt-in live foreground probe also passed; ordinary CI skips that interactive check.
- Real desktop: board focus suppressed delivery; switching to Notepad accepted it while `surface` stayed `focus` and board content remained unchanged.
- Real two-monitor check: the board stayed on the primary display. Notepad was foreground on display 2; the native bubble rectangle was `[4489,552,4867,705]`, within that display's `[2560,-183,5120,1257]` bounds. Foreground stayed the same Notepad window before and after the bubble. A later primary-screen recording likewise left Notepad foreground.
- Real star adoption produced a node with the originating source id. The subsequent Develop request was read by that source; a full board reply was submitted and the two explicit events acknowledged.
- Component checks covered 54 language/shape/size combinations for overflow and star bounds. A further 18 combinations checked star/text overlap.
- Windows installer built locally. CI packaging and macOS build results are reported on the release page. No macOS hardware interaction verdict is implied.

The desktop film is edited: waits are shortened, some input is accelerated, and the successful take is used for the star click. Bubble pixels are captured together with the working application, never composited over it. The Agent's submissions in this recording use the real MCP HTTP interface; this is not a claim of native host tool registration.

## Repeating the focused desktop check

On an interactive Windows desktop, keep the board on one monitor, focus another application on the other, and submit a bubble. To read numeric foreground/monitor evidence without moving or reading the contents of other windows:

```sh
cargo test --manifest-path src-tauri/Cargo.toml live_foreground_monitor -- --ignored --nocapture
```

`SPELLCAST_DIAG_WINDOW_ID` can identify one observed native window handle whose rectangle should also be reported. The probe only reads handles and geometry; it never activates or moves a window.

Platform references: [Windows foreground window](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow), [Windows monitor selection](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-monitorfromwindow), [macOS active screen](https://developer.apple.com/documentation/appkit/nsscreen/main).
