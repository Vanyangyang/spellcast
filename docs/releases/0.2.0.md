# Spellcast 0.2.0

This release connects desktop ideas to complete, editable board replies.

## Included

- A starred desktop bubble becomes a persistent idea with its source task attached.
- Full replies can mix text, aligned comparisons, labeled relationship graphs, and ordered storyboards.
- Users can choose options, edit blocks, reorder steps, move graph nodes, and send feedback about the selected content.
- Agents can update one block with a revision guard. A stale update is rejected; the user's draft remains available.
- Explicit feedback persists beyond the transient event history and across restart until its own source task acknowledges it.
- User-controlled memory can be saved, searched, recalled, and forgotten independently of kept ideas.
- Bubbles respect pause, focus mode, recent duplicates, and a shared limit of two active windows. Window scheduling and readiness are reported separately.
- The bundled Skill now covers ambient behavior, full board replies, source routing, local updates, acknowledgement, and host lifecycle limits.
- The project and optional editor launcher consistently use the Spellcast name.

## Download and platform scope

`Spellcast_0.2.0_x64-setup.exe` is the locally built Windows x64 NSIS installer. `spellcast-demo.mp4` is a 61-second, 1920×1080 H.264 walkthrough.

The release executable was exercised on Windows. The installer was generated successfully, but a clean-machine installation was not part of this local check. Apple Silicon and Intel macOS packages were built and bundled on GitHub Actions; neither received a macOS runtime check. Linux was not validated.

- Apple Silicon: `Spellcast_0.2.0_aarch64.dmg` (CI build, runtime unverified).

- Rust workspace: **40 tests passed**. Desktop configuration/Skill suite: **8 tests passed**.
- Real MCP request/response coverage includes a four-form reply, user selection, source-scoped listening, one-block agent update, and acknowledgement.

## Demo method and limits

The film uses the actual Windows application with a fictional rain-puzzle design scenario. Pointer and keyboard input were driven during the recording. Astra authored the reply and update, read the resulting feedback, and sent the content through the application's MCP HTTP endpoint. The film trims idle time and speeds up text entry; it does not demonstrate automatic model wakeups or a newly registered native host tool.

The model stays in its host. Feedback is queued until that host task reads it. Spellcast does not provide a background model, automatic conversation capture, or an independent scheduler. The browser preview cannot create OS bubble windows.

## Data and upgrades

The board, replies, pending explicit feedback, and memory are stored locally in SQLite. State schema 1 is migrated to schema 2; unsupported versions and corrupt state are rejected instead of silently discarded. Development fixtures use the explicit `SPELLCAST_STATE_FILE` override so they do not replace the user's normal application data.

The service binds to loopback and rejects untrusted browser origins and non-loopback Host headers. Connect only the local clients you intend to grant access to the board and memory.

New MCP tools: `spellcast_reply`, `spellcast_update`, and `spellcast_ack`. Existing tools remain available, including the loose-card layouts exposed by `spellcast_present`.
