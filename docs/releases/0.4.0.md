# Spellcast 0.4.0 — Canvas workbench and Grok Build

This is an AGPL-3.0-or-later preview. It is not a finished product. The published 0.3.0 installers do not include this workbench; 0.4.0 is the first tagged build that does.

## Changes

- Ship the Canvas workbench: editable components and named Idea compositions; workspace and task organization; a request-based replies panel; annotations; image references; content scale, wheel zoom, and a native content editor.
- Keep Codex one-step setup as MCP + Hooks + Skill, with backups and conflict checks. Direct Canvas send-back to the original task still goes through the running Codex Desktop app.
- Add Grok Build one-step setup on the same Settings page. It only writes MCP + Skill into `~/.grok` (`config.toml` `[mcp_servers.spellcast]` and `skills/spellcast/`). It is not a Codex plugin/hooks/marketplace clone, there is no `spellcast_bind_grok`, and Canvas send-back into a Grok session is not provided. Cursor, Claude Code, Windsurf, and Other stay visible but disabled.
- Document the self-contained local runtime: `npx tauri build --debug --no-bundle` produces `src-tauri/target/debug/spellcast.exe` with `frontendDist` embedded. `npm run desktop` / `tauri dev` still hot-reload against Vite at `http://127.0.0.1:47193`; without Vite, that debug process shows `ERR_CONNECTION_REFUSED`.

## Verification

- Windows library tests cover Grok TOML merge (preserving `models`, `plugins`, `marketplace`, other `mcp_servers.*`, and `[ui]`; never writing Codex paths) and complete-setup status/install for `grok` versus still-unsupported `cursor` / `claude-code` / `windsurf`. Existing Codex complete-setup tests passed in the same run. See [Grok Build setup](../reviews/2026-09-18-grok-build-entry.md).
- Windows UI checks: Codex and Grok Build are selectable; other clients remain `disabled`. A self-contained debug exe opened the Canvas and Settings without Vite on 47193; bridge health was `http://127.0.0.1:47194/api/health`. See [the self-contained runtime record](../reviews/2026-09-18-debug-selfcontained-runtime.md).
- Canvas workbench and replies evidence remains the Windows runtime records: [workbench runtime](../reviews/2026-09-14-workbench-runtime-acceptance.md) and [replies inbox](../reviews/2026-09-15-replies-inbox.md). [Codex-only setup](../reviews/2026-09-15-codex-only-entry.md) is a dated snapshot of the previous Settings UI, not 0.4.0.
- **Windows only tested.** The macOS `.dmg` files are produced by the release workflow and only pass CI packaging; they are unsigned, nobody has run them, and they are not guaranteed to work.
