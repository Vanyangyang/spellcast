# Spellcast 0.4.1 — ship the 0.4.0 workbench

Product content is the same as [0.4.0](0.4.0.md): Canvas workbench, Codex one-step setup, and Grok Build MCP + Skill. `v0.4.0` was tagged, but the GitHub Release workflow did not finish: Windows NSIS built, both macOS jobs failed at `cargo test --manifest-path src-tauri/Cargo.toml --lib`, and no public Release was published.

## Changes

- Keep nested libtest process-lock coverage on Windows only (`two_processes_contend_same_profile`). Re-spawning the Tauri `--lib` test binary as a child is reliable on Windows CI; on macOS that child links AppKit/WebKit and does not come up as a nested harness, so the lock-ready file never appears.
- Treat Unix lock-busy errno values (`EAGAIN`/`EWOULDBLOCK`/`EBUSY`) the same as the existing Windows sharing/lock codes when a second installer process is already holding `spellcast-setup.lock`.

## Verification

- Windows: `cargo test --manifest-path src-tauri/Cargo.toml --lib complete_setup -- --test-threads=1` after the gate. The product checks from [0.4.0](0.4.0.md) still apply.
- **Windows only tested.** macOS `.dmg` files from this tag are CI packaging only; unsigned and unrun.
