# Spellcast 0.3.0 — independent asides

This is the first build published under the GNU Affero General Public License v3.0 or later. The earlier MIT-licensed previews (0.1.0–0.2.1) were withdrawn from Releases on the same day; copies already obtained keep their original terms.

## Changes

- Add the independent observer protocol to the bridge and the bundled Skill. `spellcast_checkpoint(source_id, snapshot)` accepts a short project snapshot at a meaningful checkpoint and, when admitted, returns an observation brief and a one-shot ticket. The host spawns a fresh isolated child with that brief only; the child calls `spellcast_observer_complete(observer_id, thought)` itself, and `thought=null` completes quietly. The parent receives only a delivery status. Newer snapshots invalidate pending tickets; `snapshot=null` cancels. Spellcast still does not run a model or start observers on a timer.
- Keep a focused board card fully inside the plane. The outermost fragments used to land half outside a narrow window when a bubble was opened by double-click; the horizontal position is now clamped so the whole card is readable.
- Replace the release film with the calendar demo: a real desktop calendar in progress, task-grounded bubbles from the host agent, a kept bubble becoming a board fragment, the four spatial forms, and a short teaser for the Everything board.
- Relicense to AGPL-3.0-or-later across `LICENSE`, the Cargo workspace, the desktop crate, and the npm package.

## Verification

- Windows: bridge tests cover sparse admission, bounded input, quiet completion, source binding, replay rejection, changed projects, cancellation, expiry, pause and restart invalidation. The full workspace suite and the desktop crate's `--lib` tests passed locally before tagging; CI repeats both on every target.
- Real Codex CLI spawned an isolated child with no history fork while the parent continued its own work. The child called the registered `spellcast_observer_complete` natively with a project-grounded thought; the parent received only `accepted`, and the desktop emitted the bubble bound to the original calendar source. See [the observer record](../reviews/2026-09-06-independent-observer.md) for the exact boundary of that evidence.
- Real user input on the calendar demo: bubbles appeared on the display of the foreground calendar window, a starred bubble became a board fragment, drag and double-click behaved as documented, and the clamped card fix was confirmed on the rebuilt desktop app. See the [bubble acceptance record](../reviews/2026-09-06-bubble-acceptance-record.md).
- **Windows only tested.** The macOS `.dmg` files are produced by the release workflow and only pass CI packaging; they are unsigned, nobody has run them, and they are not guaranteed to work.

The demo film is edited: waits are shortened, some input is accelerated, and captions were added afterwards. Bubble pixels are captured together with the working application, never composited over it.
