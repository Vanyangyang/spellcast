# Spellcast 0.4.5 — Codex file install and hook-trust Check

Windows is the only tested platform.

## Changes

- **Settings install writes Codex files directly.** One click merges Spellcast MCP, the Skill, and user `~/.codex/hooks.json`. It does not call `codex.exe`, does not write `trusted_hash`, and does not install a plugin plus user hooks together.
- **Check reads Codex `/hooks` trust from files.** After the user trusts SessionStart and UserPromptSubmit, Settings compares the current hook definitions with `[hooks.state]` `trusted_hash` and shows Trusted. Missing trust stays pending; a hash mismatch asks to trust again. Plugin leftover hashes and commented lines are not treated as user-hook trust.
- **Aside switch label is Recommended** (was Optional) in Chinese, English, and Japanese.

## Verification

- `cargo test --manifest-path src-tauri/Cargo.toml --lib complete_setup::`
- `npm run check:complete-setup-ui`
- Local `npm run desktop` Settings Check against a real Codex `config.toml` that already had matching `trusted_hash` entries: Hooks **Trusted**, status **Installed · Hooks trusted**. Check did not write trust or call the CLI.
