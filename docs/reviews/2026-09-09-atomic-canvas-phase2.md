# 原子画布第二阶段：批量编排、组合与多位置反馈

状态：第二阶段工程实现已整合，74 项 Rust 测试、10 项第二阶段原生检查、9 项第一阶段原生回归，以及同一测试数据库的进程重启检查通过。未提交或推送。本记录描述当时的第二阶段完成范围：跨对象数据联动在写下本文时尚未实施。之后的第三阶段本机原生复验见[第三阶段记录](2026-09-09-atomic-canvas-phase3.md)。本记录不宣称真实用户创意工作或原生宿主 Agent 回传已验收。

## 已实现

- 原生文字、图片、矩形和椭圆直接保存为独立内容对象，拥有稳定 ID、内容版本与来源。文字标题属于可见内容，不依赖选中时的操作栏。旧节点、结构化回复和完整交互作品继续映射为对象，不复制正文或自动拆散旧回复。
- 新增 MCP 工具 `spellcast_canvas_batch`。一次提交可创建对象、修改提供的内容字段、更新一个旧回复块、调整明确目标的呈现、组合或解组；每次最多 64 个操作、128 个读依赖。创建应先于引用新 ID 的操作。
- 内容、呈现和组合分别检查版本。整批模拟通过后才写入；失败时保留完整提案，返回逐目标状态，包括本可通过的目标。缺失图片等资源错误也不会留下半批内容。
- `request_id` 的相同来源、相同载荷重试返回已有结果，先于会变化的反馈和资源检查。已应用、已放弃记录保留在会话中，不因超过 256 条而丢失幂等性；改变载荷需使用新 ID。
- 用户编辑过的正文、调整过的呈现和未分配给 Agent 的用户对象受到保护。Agent 可对用户对象留下提案，不能通过整条旧回复替换绕过保护；其他任务的内容只能作为引用。提案界面显示完整的当前值与请求值，按已审阅版本应用，或明确放弃。
- 组合的 ID、版本、成员和来源持久化。支持嵌套、单一父组与环校验，整体移动与一次撤销/重做、解组及层级选择。嵌套解组会检查父组版本；彻底删除内容还需声明祖先组合版本。移除呈现保留正文、位置、草稿和组合关系。
- 图片选区按实际图像内容计算归一化坐标，适应缩放和留白，并携带原资源身份。多选反馈携带多个对象的准确内容版本；交互作品使用其已声明的参数与选择，不猜测 iframe 内部 DOM。
- 一条反馈只送往一个明确选择的任务，其他来源的对象是上下文。发送前等待作品参数保存，再获取当前锚点；批量响应通过 `response_request_id` 和 `response_object_ids` 关联原反馈。读取、响应和确认处理仍是不同状态。
- 复用现有会话快照、SQLite 保存和反馈队列。原生与旧内容的草稿均保留恢复路径；原生草稿存储损坏或并发改变时保留原字节并提示，未落盘的草稿阻止移除。布局重试保留完整请求和版本，不默默重设预期版本。

原生图片可使用受控本地作品资源、HTTP(S) 图片或不超过 2 MB 的 PNG/JPEG/WebP base64 数据。完整 Web 作品继续隔离运行；当前没有任意 HTML 原生对象或跨对象响应式引擎。

独立 Sol 静态审查指出的回放顺序、资源失败提案、删除的组合依赖和 Create 目标状态遗漏已修复。没有采纳“响应读版本必须始终等于旧反馈锚点版本”：Agent 可以明确重读并声明当前版本，原反馈仍保留原版本和选区；宿主不据此声称它理解了旧内容，也不推断未声明的陈旧依赖。这遵循[方案中的依赖边界](2026-09-08-atomic-canvas-decision.md)。

原生输入发生在真实 Tauri WebView。样本创建、模型响应和确认是确定性的直接 MCP 协议检查；未绑定或唤醒真实 Agent 任务，不把它们当作 Codex 注入新工具、实际原任务回传或外部用户验收。网络中断、损坏 localStorage 和恢复测试字节均明确属于 `DIAG_ONLY` 注入。首次检查发现的组合失败状态未刷新问题已修复，最终构建重新通过完整检查。
