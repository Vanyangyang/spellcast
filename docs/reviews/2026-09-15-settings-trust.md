# 设置页：真实 Hook 信任状态与必需接入

## 修正

旧安装器在核验插件文件后固定返回 `installed_pending_trust`，前端也把 `verified` 显示为“未验证”。这将“没有读取信任状态”误表述成“尚未信任”。

现在通过本机 Codex 的只读 `hooks/list` 查询，由 Codex 自己计算当前 Hook hash 和信任状态。查询限定安装用户及 `CODEX_HOME`，核对返回工作目录、Spellcast 插件身份、当前版本的 `hooks/hooks.json` 路径、两项事件及启用状态。不会创建任务、运行 Hook、提交模型回合或写入信任。

- 两项都启用且可信：显示“已安装 · Hooks 已信任”。
- 确认未信任：显示“待信任”，指向 Codex `/hooks`。
- 内容已变更：明确需要重新信任。
- 已停用：指向启用操作，不误称尚未信任。
- 旧版接口、查询失败、来源不匹配或返回不完整：保留已安装状态，显示信任未核验；不会要求重复安装或声称未信任。

设置页优先展示 Codex 必需接入，分别说明 Hooks、Skill、MCP 的用途和状态。首次按钮为“安装 Hooks + Skill（必需）”，已安装后为“更新 Hooks + Skill”；一次操作仍完整接入三项。新增只读“重新检查”。客户端名称和最近活动直接显示在接入标题下方；旁念开关独立，MCP 地址、其他禁用客户端和安装路径归入默认折叠的连接诊断。字体、间距、滚动和窄窗口布局一并整理。
