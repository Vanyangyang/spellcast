# Everything Canvas：原子表达与自由组合

状态：主代理经两轮真实 Fable 独立评审后收敛的工程方案。用户已确认的是“加速创意工作”和“提供原子表达，由 Agent 自由选择组合”。2026-09-09 已整合第一、二阶段，并完成限定范围的本机原生检查，详见[第一阶段记录](2026-09-09-atomic-canvas-phase1.md)和[第二阶段记录](2026-09-09-atomic-canvas-phase2.md)。同日稍后完成第三阶段有限数据链的本机原生复验，详见[第三阶段记录](2026-09-09-atomic-canvas-phase3.md)。真实 Agent 创意回合、原生宿主 Agent 回传和整体体验仍未据此宣告通过。

## 采用的路线

画布是共同工作的空间。内容对象可以独立呈现、选择、引用、修改，也可以组合成一次表达。回复保留来源、上下文与交流记录，但不决定屏幕上必须有几个框。

卡片保留为可选的呈现形式。标题栏、边框和独立滚动区不再成为所有内容的必经外壳；选择轮廓、拖动手柄、焦点提示与必要的层级导航属于操作反馈，按交互状态出现。

原生文字、图片、矢量/几何、连接和完整交互作品都可以参加组合。对比、流程、分支、故事板既可由对象组成，也可保持整体；一套机制实验可以是完整作品。原子表示明确的操作边界，不表示必须拆到最小像素或现有 ReplyBlock。

## 最少必须成立的契约

| 边界 | 决定 |
| --- | --- |
| 内容与来源 | 新对象有稳定 ID、内容版本和来源引用，ID 不由 reply/block 路径决定。现有 ReplyBlock 可以被适配为旧内容对象，不能成为新表达能力的永久类型上限。 |
| 内容与呈现 | 呈现记录保存位置、尺寸、z 序、样式、自身版本及移除状态。首版一对象一处呈现即可，不先建多实例系统；移除时保留内容与原位置/尺寸，恢复时仍使用这些记录；彻底删除内容是不同操作。 |
| 组合 | 成员关系与组合 ID、自身版本一起持久化，支持整体移动和解组。复用画布存储，无强制外框；先做简单成员/父子关系与环校验，不引入通用约束求解器。 |
| 修改与冲突 | 新对象使用对象级内容版本。一次请求可以原子地修改多个相关对象，并声明所读的对象/呈现/组合版本及各写入目标的预期版本。全部校验后才提交；失败时逐目标返回冲突或本可通过状态，整批不写入并保留提案。 |
| 用户改动 | Agent 提交本轮目标的字段修改，不用整条回复替换绕过保护。用户修改过的内容默认保留；若新建议涉及这些修改，保留为可应用的提案，或按用户明确的修改请求处理。 |
| Agent 布局 | 新增受控的对象/布局批量修改入口，让 Agent 能创建和编排表达。用户移动或调整过的位置默认保留；重新编排只作用于明确目标，不能默默重排整板。布局版本不与无关的内容编辑绑成一个锁。 |
| 输入 | 未激活的文字/作品先由宿主处理选择与移动，双击、Enter 或明确的激活动作后原位编辑/交互，退出可回到选择态。层级入口始终由宿主掌握；激活后作品内控件优先接收自己的输入。空格或中键平移，画布快捷键仅在适用焦点下响应，拖动不依赖常驻卡片标题栏。 |
| 反馈 | 一次反馈携带多个稳定锚点：对象、确切内容/作品版本，以及可选子项、区域、参数状态。区域携带资源身份与坐标单位；文本/图片/作品各用其真实能力，宿主不猜测任意 DOM 或图片图层。 |
| 接收任务 | 一次反馈明确送往一个任务。其他来源对象可以作为引用上下文，不自动向多个来源 Agent 广播同一请求。 |
| 可执行作品 | 继续隔离运行。在 bundle manifest 中声明可识别锚点与有限输入/输出；宿主验证并转发声明的数据，不开放宿主 DOM 或命令。输入由宿主管理并按上游重算，与作品自己的 state/state_revision 分开。没有声明的内部内容仍作为整个作品操作。 |

对象级版本不是字段级自动合并，也不要求 CRDT。批量请求的原子范围是这次需要保持一致的变更集合，不是整张画布。若把冲突的 A 与无关 B 放进同批，整批仍会失败；Agent 可根据逐目标状态缩窄范围后重提。B 若声明依赖旧 A，就应报告冲突；宿主无法推断 Agent 未声明的依赖，不承诺自动发现所有陈旧推导。

新建对象与组合使用请求方生成的不透明稳定 ID，提交前检查重复及批内引用；同一批可引用自己新建的对象。请求携带稳定 request_id 以支持幂等重试。待应用提案也用 request_id 定位，保存完整变更、预期版本与冲突信息，持久化在同一会话快照中；应用、放弃或明确清理后关闭。它是统一的待应用修改记录，不另加一套画布对象或存储引擎。

首版跨对象联动只验证一条明确的数据链：参数 → 图表/作品与原生数值说明。原生说明仅做无表达式的值显示绑定（将受控输入显示在指定文本字段），不执行代码或模板表达式。需要完整动态叙述时留在作品内。连接先只允许有限数字、字符串、布尔值或 null，校验类型并限制每个对象的输入快照不超过 64 KB；无环、单向传递。复杂双向关系或计算模型先保留在一个完整作品内，不建设通用响应式引擎。

重开时先恢复来源对象/作品自己的状态，等待其就绪并重新提供输出，再计算下游输入。宿主不以旧输入覆盖作品自身保存状态；输入副本不成为第二个权威来源。上游未就绪或失败时显式传递 unavailable；若界面保留旧值，必须标明陈旧，不将它当作当前有效值继续传播。

## 从 Fable 评审采纳与修订的点

| 评审意见 | 主代理处理 |
| --- | --- |
| 当前卡片同时承担保存键、交互门、拖动与删除单位；改名不能解除限制 | 采纳。先拆职责与删除语义，再开放原位操作和多个对象。 |
| 当前没有 Agent 画布布局工具 | 已核实，列为新增必需能力。不能把自由编排写成已实现。 |
| 回复级锁及三类用户状态保留不足以保证局部内容修改安全 | 采纳。新对象使用自身版本，保留用户改动与冲突提案；旧回复保持原兼容语义。 |
| 对象级版本意味着十二个候选要十二次写入 | 不采纳这个必然关系。版本粒度与请求批量粒度可以分开，一次事务可提交多个有各自版本的修改。候选集仍可整体操作，也可寻址其中成员。 |
| 叠放对象难选，因此需要恢复卡片/容器 | 采纳可选性问题，不据此恢复固定外框。选中轮廓、遮挡提示和必要的层级选择可以解决操作歧义；这些与卡片样式是不同职责。具体可用性仍需真实输入验证。 |
| 跨作品联动可能迫使取消隔离或把整个工作面变成一个作品 | 采纳“必须有数据通道”的要求，不取消隔离。首条链用声明的数据接口验证；高耦合实验可作为一个整体作品存在。 |
| 给 placement 加 group_id 即可表达组合 | 可作为迁移实现手段；最终必须能稳定定位组合与成员，并定义整体操作、解组和成员删除行为。仅有分组标签不代表这些能力已经成立。 |

## 最小实施顺序

1. **身份、移除与原位操作。** 先确定对象、组合和呈现的身份/版本，呈现记录包括 z 序与移除后的原位置。作品状态、草稿与反馈的新路径统一定位 object_id；旧 reply/block 字段通过映射兼容，不形成第二套权威身份。把“移除呈现”和“删除内容”分开，保留旧数据与引用的恢复路径；加入选择/激活状态，解除统一阅读器入口和卡片尺寸下限。旧回复继续作为整体对象存在，不自动拆散用户现有排布。
2. **让 Agent 真正组合并接收反馈。** 加入对象批量修改、受控布局、稳定组合、多锚点反馈和版本冲突返回，完成下表前两个创意场景。复用现有资源、状态、反馈队列与持久化，不换渲染引擎或另建协作框架。
3. **验证一条跨对象联动链。** 在原生对象与隔离作品之间验证有限输入/输出及状态恢复，再按创意任务需要扩充表达能力。未通过此步骤前，不宣称任意作品可自由联动。

## 用真实创意工作验收

| 场景 | 必须看到的结果 | 未通过意味着什么 |
| --- | --- | --- |
| 命名/剧情发散 | Agent 展开候选；用户改一个标题并要求合并两个方向；下一轮只更新相关部分，保留用户改动与其他方向，刷新后仍可追踪。至少包含一次真实版本冲突。 | 组合或更新粒度仍限制创意推进。 |
| 视觉局部修改 | 主图、局部选区与候选变化同处工作面；用户可在叠放中选对目标、比较或替换，并从一次误移除中恢复内容。 | 选择、版本或移除语义尚不可用，去边框没有解决问题。 |
| 机制探索 | 用户改变一个参数，图表/作品与原生数值说明通过声明连接更新；作品自己的保存状态不被输入覆盖。当前值和选区可交回原任务，刷新可恢复并重算；上游失败明确显示不可用，不吞掉其他对象。 | 数据接口、状态归属或失败边界还不足以支撑跨对象组合。 |
