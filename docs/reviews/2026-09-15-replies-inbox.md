# 回复面板整理与验收

## 已实现

- 以每次显式发送为单位展示请求，主内容是用户留言、处理状态及可定位的当前画布结果。原点子正文和投递过程折叠，长标题最多显示两行并保留完整悬停标题。
- 面板打开时跟随当前 Canvas 的工作区和任务筛选；任务选项限定在所选工作区内，标签计数跟随筛选。可主动切到全部工作区或工作区未记录。
- 请求归属优先使用实际投递的工作区和任务，再使用身份匹配的绑定；引用其他工作区的对象不改变接收任务。收件人未知时，不从引用内容推断任务归属。
- 待跟进、已回写/已处理、历史记录分开。旧 `selection`/`reply_edit` 自动反馈和没有原生交付记录的 `queued` 请求进入历史；不根据时间猜测任务完成，也不删除记录。历史项不提供自动重投入口。
- 结果预览明确标为“当前画布内容”，不冒充不可恢复的历史 Agent 回复。已处理但没有关联结果时明确说明，不给出误导性的查看回复按钮。
- 同步失败保留最后读到的记录，并显示刷新入口；用户主动重试后更新回执，保留已有防止旧查询覆盖新回执的逻辑。
- 固定顶部筛选区，记录区独立滚动。窄窗口采用两列筛选和独立搜索行；标签页支持左右键及 Home/End，选中状态和计数有可访问标记。中、英、日文标签同步更新。
