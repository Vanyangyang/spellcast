# 原生 Codex 桌面交付验收

用户在 Canvas 提交后，当前运行的 Codex Desktop 直接接手对应原任务，结果回到同一对象。新请求不再写入独立 CLI 的 `thread/queue/add`。旧历史保留为“历史请求 · 尚未确认接手”，不自动重发。

## 实现

- 使用桌面现有 App tools 的本地 IPC：目录握手确认 `codex_app` 命名空间与所需接口，`read_thread` 核对精确任务和工作区后调用 `send_message_to_thread`。Explorer 启动的 Spellcast 通过本地命名管道发现，已在实际运行中验证。
- 只传原任务、宿主和用户请求，不覆盖模型、推理强度、权限或工作目录；不创建新任务或额外模型运行时。
- 画布输入旁分别显示发送、原任务读取、结果返回和处理状态，显示需要用户输入或权限确认等宿主状态。
- 请求持久化，响应携带反馈序号和原对象版本；传输结果不明、已接受却未返回内容时仅核对，不能重发。原任务结束本身不证明该请求已执行。
- 已接受的请求保存原始任务、工作区与发送回执。后续重新关联来源不能改写监测对象；核对不覆盖发送时间和原回执。真正的读取、回复、确认优先于迟到的传输结果。
