# Canvas 接收任务：Browser Use 验收

用户要求用 Browser Use 完成界面验证。本轮使用 Codex In-app Browser，通过真实点选、输入、任务改派确认与发送操作验证当前前端；没有调用 Windows 原生界面控制。

## 已确认

- 已有内容默认展示原工作区与原 Codex 任务。
- 任务下拉只包含当前工作区；切换到另一个工作区时清空当前可见任务，发送按钮禁用。
- 选择替代任务后出现警告，包含原任务、新任务及各自工作区。取消恢复原工作区和原任务，文字草稿完整保留。
- 分别点击默认原任务发送、确认改派后发送，隔离记录中的 `source_id`、`target_thread_id` 与所选任务一致，内容锚点仍为同一个 Canvas 对象及版本。
- 未选内容时，输入、任务选择与发送都禁用；工作区选择不展示全部任务。
- 当前 1280×720 浏览器视口下，工作区、Codex 任务与“发送到 Codex”按钮排列正常。

## 浏览器发现并修复的问题

旧实现改派时复制了当前草稿，新任务发送完成后只清除新任务的副本。重新选中原内容会恢复旧任务下已发送的文字，有误重发风险。

现在改派会先保存新目标草稿，成功后按原版本移除旧副本；他窗口较新的修改不被删除。浏览器重新执行“改派 → 发送 → 取消选中 → 重新选中”，确认草稿为空、发送按钮禁用。隔离发送记录没有额外请求。
