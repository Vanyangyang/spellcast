## 建议调整的顺序与边界

1. 把稳定子对象锚点与有限内容引用放在同一轮。先让比较项、分镜步骤能引用同一 Idea 内的图片/局部画面，并能被准确指向。通用持久注释界面可以随后补，但应复用同一套指向语义。
2. 第一版引用固定画面或固定状态，明确更新；不要让被比较的内容悄悄变化。只保存版本号不足以保证可以恢复历史内容：作品当前保存路径会覆盖 state 并递增 state_revision（`spellcast-core/src/reply.rs:478-498`）。需要保证被引用资源/状态可读取，或者清楚显示失效，不能静默替换成最新内容。
3. 引用不改变成员归属和内容所有权。移除展示、解散组合、原内容变化和删除的行为需要逐一规定。第一版不开放任意递归引用或跨工作区共享。
4. 编排意图作为初始排版和用户明确重新编排的依据。用户手调后不因普通内容更新重新排列；并置也不生成事实关系线。没有比较维度的探索可先用并置组合，不必填写占位维度。
5. 轻量文字格式在原生 text 和结构块 text 两条路径一致实现；显示、编辑、保存、选区应使用一致的内容语义。保留安全渲染，不引入任意 HTML。
6. 紧凑作品复用现有沙箱、状态保存、停止、失败和冲突处理。引用预览不应自动启动第二份可写作品。现有源码已折叠，重点是减少常驻控件、解除不合适的最小高度。

## 第一轮可验收流程

- 同一 Idea 内有两张具体画面，比较项或分镜步骤引用它们，用户无需另造 Web 作品。
- 点击某一项/步骤或圈选画面局部，能看到明确选中反馈；发送携带稳定子对象、内容版本和引用快照。
- 改标题、调整顺序或移动画面，不让指向错位；原图更新时旧引用保持明确，用户可选择更新；删除或失效有可理解提示。
- 编辑、圈选、布局和选择只保存到 Canvas；仅最后点击发送才回到默认原 Codex 任务。切换任务仍需确认。
- 原任务读到准确目标并只修改所指内容，保留用户修改和布局；刷新/重启后引用和必要状态仍可用。

此流程通过后，再补文字格式和少量编排意图、持久注释、紧凑作品及表达示例。问题主要在协议、渲染和交互闭环，无需先引入专门的组装模型。
