## 1. 目标与范围

让用户从一次玩家选择出发，定位相关设计对象，试验一项数值改动，比较前后结果并采用方案。范围包括：

- 内容、规则、钩子与现有流程步骤/选择的关联和双向定位。
- 独立保存的数值候选及其基准。
- 项目内持久保存的完整试走与来源快照。
- 给定相同输入和选择意图的重放、分歧说明与对照。
- 采用候选时保留理由、版本和试走依据。

沿用原 Canvas、系统叠加图、现有对象身份、草稿、锁定、历史和访问控制。真实内容限定为用户提供的新 R0–R2 规划；技术测试使用隔离数据。

## 2. 设计关联

在内容/规则/钩子侧增加可选的结构化定位信息，引用本项目的流程 ID、步骤 ID，以及可选的选择 ID。钩子可进一步说明线索、动作、回报或继续动机；规则/内容允许说明其关联用途。

- 引用实际对象和已有步骤/选择，不复制一份设计正文，不增加强制的“玩家时刻”对象类型。
- 挂接关联只改拥有该关联的对象；锁定的流程骨架无需因此解锁或产生新版本。
- 保留现有对象间的使用、依赖、归属和先后关系；上述关联补充具体位置。
- 共用系统、参数、规则和素材可独立存在，不强制所有对象必须绑定流程。
- 校验同项目、正确目标类型、步骤存在、选择属于该步骤。禁止删除被有效关联的步骤/选择，提示引用对象及解除关联入口；归档/导入/历史恢复保持可解释的一致性。
- 缺省可选字段不改变旧对象的序列化结果；已有对象不自动补值或转换。
- 在流程查看/试走中显示关联设计及其来源版本，并能进入相应对象；对象编辑中能返回具体流程位置。

自动报告只能描述可确定的路径事实，例如“步骤已到达”“选择已执行”“回报步骤未到达”。不要自动报告“钩子兑现”“玩家已理解”“体验有效”。

## 3. 独立数值候选

候选属于项目，具有稳定 ID、版本、目标参数、基准快照/版本、候选值和修改理由。保存候选不修改当前参数，不要求解锁当前参数，也不使仅依赖当前参数的旧试走过期。

- 使用现有有限数值与约束检查。第一段只处理明确的数值候选，不实现任意表达式或新模拟引擎。
- 当前采用值、候选值和既有使用方的局部覆盖值分别展示。
- 试走可以显式选候选，并记录此次如何得到实际初值；局部覆盖继续优先生效，界面说明候选对该使用方未生效的原因。
- 原有 `parameter.variants` 数据保留兼容。若提供转为独立候选的操作，应由用户明确触发；不自动重写真实项目旧数据。
- 候选使用的基准与后来参数的有效定义发生变化时，显示差异并阻止静默采用。锁定标记、候选列表等非执行字段与实际规则/输入变化应分开判断；完整来源快照仍保留。

## 4. 完整试走与恢复

把可引用的完整试走存入项目的本地数据层，随项目导出/导入保留。界面状态可以继续单独保存；轨迹不再只依赖当前/上一次的浏览器存储槽。

- 记录流程定义、关联设计、参数与候选的必要快照/版本、实际初值、选择序列、前后状态、手动输入及时间。
- 来源数据与预演输入分离；试走不会写回当前设计数值。
- 被比较或采用记录引用的试走版本不得被后续继续、回退或重置覆盖。采用明确的保存版本/不可变快照策略；活动检查点与历史证据要分清。
- 新开更多试走后，已保存的旧结果仍能访问。不要把不同试走塞回两个循环覆盖的槽位。
- 保留现有单独 JSON 导出；开发记录摘要应引用实际保存的轨迹，不能承诺一个可能被覆盖的“完整本地记录”。
- 对旧本机轨迹提供有校验、可去重的恢复途径；持久化成功前不删除原数据，损坏或版本不兼容时显示具体原因。
- 对定义、事件数量、大小、类型和有限数字做边界校验。沿用现有 request ID、版本冲突与访问控制原则。

## 5. 重放与比较

基于保存的试走，用相同初始输入和选择意图运行当前明确支持的条件与设值/加减。候选改变的输入需明确标出。

- 原轨迹保持不变。重放是新的试走，关联基准轨迹及候选。
- 遇到被删除/不存在的选择、不满足的条件或路径分歧，停止并解释第一处分歧，不偷偷换路。
- 对比实际有效初值、每步变化与最终/阻断状态；不把模型预演表述成 Unity 或真实玩家验收。
- 遇到手动/外部步骤默认暂停。只有用户明确选择时才复用旧结果，并标为“手动假设”；输入或依赖有变化时突出显示，不能自动提升为新方案的验证结果。
- 不新增随机模拟、概率经济系统或叙事运行时。

## 6. 采用与持久化

采用操作显示目标参数、前后差异、影响范围、候选基准及所选试走依据，并要求填写采用理由。

- 仍遵守目标对象的显式解锁与最新版本检查。冲突保留草稿，不能覆盖较新的编辑。
- 仅更新指定的共用参数值；使用方的局部覆盖不变。
- 参数修改、采用依据及必要历史/请求回执在事务中一致保存，保留候选 ID/版本和试走 ID/版本。
- 更早的候选和记录可回看；恢复历史、归档和导入不能绕过引用与锁定检查。
- 如需数据库或导出格式升级，保留旧版本读取/导入；不得重建、清空真实数据库。

## 7. 界面与边界

- 编辑和对照使用主要窗口面积，目录与辅助说明可收起；不把完整编辑塞进画布卡片。
- 从关联对象进入步骤/选择，再回到对象时保留合理的选择和工作位置。
- 示例明确标记且只在内存中运行；真实写入只来自用户操作。测试项目、候选和轨迹放在隔离 fixture/临时数据库中。
- 此段暂缓素材制作面板、素材生成服务、ComfyUI、inkjs、LDtk、3D 检查工具及真实游戏配置接入。
- 本地游戏内容继续留在用户数据区。实现者不操作真实 VESPERIX 项目数据，不调用 Unity，不发送外部任务，不安装付费生成能力。

## 8. 必要验收

1. 在锁定流程上关联内容、规则和钩子，流程版本不变；能双向定位对应步骤/选择。
2. 悬空引用、跨项目引用、删除被引用步骤、历史恢复及导入冲突有明确处理，不静默丢失。
3. 路径报告只陈述到达/执行事实，未到达的反馈可定位；不自动给出体验成功结论。
4. 新候选不修改当前参数；选择候选试走时初值来源清楚，局部覆盖保持原语义。
5. 对比标明第一处分歧；手动步骤需要明确输入或显式复用假设；原轨迹不变。
6. 采用产生正确的参数版本与依据，旧版本或锁定目标不能被绕过，局部覆盖不变。
7. 连续多次试走、重启、导出/导入后，被引用的候选、轨迹和采用理由仍可访问；旧格式兼容。
8. 主要编辑与对照视图在 1920、1320、880 宽度可操作；原 Canvas 和现有规划功能没有回归。
