# Web works, artifacts, and dataflow

Use `spellcast_artifact` for HTML/CSS/JavaScript, SVG, Canvas, charts, three-dimensional scenes, media or a custom interactive work. Build its directory in your existing host; include local libraries, fonts, assets, original source and dependency licenses. Any appropriate library may be bundled; the example engines are not a whitelist. Publish into a stable `reply_id` and `block_id`, with the current `expected_revision` when updating. Other blocks and saved user parameters remain intact. Read `spellcast_artifact_read` for its manifest, source and runtime contract.

Inside the work, await `window.spellcast.ready` and restore controls from the returned state. `window.spellcast.setState({...})` saves JSON parameters, and `window.spellcast.select({...})` records a meaningful selection with stable object IDs, asset names, region coordinates or time ranges. These calls do not invoke a model. Register `onRestore` without echoing saved state back; dispose renderers, workers and media on `pagehide`. Network resources must be brought into the work by the host. The frame's message channel does not execute host commands.

When explicit feedback includes `artifact_context`, inspect that exact bundle and selection as well as the current board. Update the same work, pass the answered `feedback_sequences` to `spellcast_artifact`, and acknowledge only after the result is saved. A rendered work, an interactive work, a successful state save and an actual originating-task response are separate checks. If new tools are absent from the host's catalog, report that gap; a direct transport test does not establish native registration.

For a work whose source the user edited, publish a separate candidate, then use `patch_reply` in `spellcast_canvas_batch` to propose its saved bundle on the original object. This keeps the current work and its parameters available during review.

For a finite data connection, publish `io: {inputs: {port: "number"}, outputs: {port: "number"}}` in the bundle manifest. Port types are `number`, `string`, `boolean`, or `null`; numbers must be finite, each string at most 16000 UTF-8 bytes, and each object's input snapshot at most 64000 bytes. The canvas forwards only declared ports along a one-way acyclic graph. Use batch `bind` with the target object's content revision and complete `bindings` list; each entry is `{from: {object_id, block_id, port}, to: {block_id, port}}`. Declare content reads for every upstream object. Native text uses `to: {port: "text"}` to display a value without expressions; its saved literal text stays available when disconnected. Creation can include `bindings` in the same operation.

Inside a work, use `spellcast.inputs` and `onInputs(snapshot => ...)` separately from saved `state`. Publish scalars with `publishOutputs(values, snapshot.revision)` using the input revision that the calculation actually read, especially for asynchronous work. `unavailable` means there is no current value: show that condition and do not propagate cached success. Startup restores each work's own state, then waits for fresh output before rebuilding inputs. Stopping or failing an upstream work invalidates its downstream values. This interface does not execute host code or infer internal DOM structure.
